# yunshu-nix 使用手册

本文档说明如何把一个已剥离 GUI 的 YunShu headless 后台服务，通过
NixOS declarative container 部署成局域网透明网关或私有代理。默认使用
`gateway` 模式复用 YunShu 自带的 TUN 分流；也可以使用 `private_proxy` 模式
通过 3proxy 暴露 HTTP/SOCKS 代理。

最终形态：

```text
路由器/局域网设备
      |
      | 默认网关 = 容器 IP
      v
yunshu-router 容器
      |
      v
yunshu-daemon / yunshu-updater + TUN 分流
```

## 1. 前置条件

- 一台可运行 NixOS 的 x86_64 宿主机
- Nix 已启用 flakes：

  ```nix
  nix.settings.experimental-features = [ "nix-command" "flakes" ];
  ```

- 宿主机内核支持 `tun` 模块
- 宿主机已有或可以创建 bridge，例如 `br0`
- 项目目录已包含 `dist/yunshu-headless/`，里面有：

  ```text
  opt/apps/yunshu/files/bin/
  opt/apps/yunshu/files/system/
  opt/apps/yunshu/files/config/version.ini
  ```

如果还没有 headless payload，可在项目根目录运行：

```sh
./headless/build-headless.sh
```

## 2. 宿主机 flake 配置

把本项目作为 flake input，并导入 `yunshu-router.nixosModules.container`。

```nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";

    yunshu-router = {
      url = "path:/home/allenmagic/Projects/yunshu-nix";
      inputs.nixpkgs.follows = "nixpkgs";
    };
  };

  outputs = { nixpkgs, yunshu-router, ... }: {
    nixosConfigurations.host = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [
        yunshu-router.nixosModules.container

        {
          networking.hostName = "router-host";

          networking.bridges.br0.interfaces = [ "eth0" ];
          networking.interfaces.br0.useDHCP = true;

          yunshu.container = {
            enable = true;
            mode = "gateway";
            networkMode = "bridge";
            bridge = "br0";
            lanAddress = "192.168.10.3/24";
          };
        }
      ];
    };
  };
}
```

如果宿主机物理网卡不是 `eth0`，请改成实际名称。`lanAddress` 需要与局域网同网段，
并且不要和现有设备冲突。

## 3. 部署

```sh
sudo nixos-rebuild switch --flake .#host
```

查看容器是否运行：

```sh
sudo nixos-container status yunshu-router
```

查看容器内的关键服务：

```sh
sudo nixos-container run yunshu-router -- \
  systemctl status yunshu-init yunshu-daemon yunshu-updater
```

## 4. 首次登录

首次登录或 token 过期时，浏览器打开：

```text
http://<容器IP>:8080
```

例如 gateway/bridge 模式下是 `http://192.168.10.3:8080`。页面会自动显示飞书
SSO 登录链接，完成 SSO 后页面会自动刷新并显示“登录成功”。同时也可以从 journal
查看原始输出：

```sh
sudo journalctl -M yunshu-router -u yunshu-login -f
```

登录成功后，`yunshu-login.service` 会在容器内写入：

```text
/var/lib/yunshu/config/.logged-in
```

之后重启容器或宿主机，不会再次触发交互式登录。

也可以手动在容器内执行：

```sh
sudo nixos-container run yunshu-router -- yunshu -c <企业码> -l
```

## 5. 验证代理

`gateway` 模式下，把局域网测试机的默认网关指向容器 IP：

```sh
ip route replace default via 192.168.10.3 dev eth0
```

然后直接访问应走 VPN 的地址或普通公网地址，确认不用配置代理即可通信。

## 6. 容器网络模式

### gateway 模式（默认）

要求 `networkMode = "bridge"`。容器开启 IP 转发、关闭 ICMP redirect，
并放行 `eth0 <-> tun0` 转发；局域网设备把默认网关指向容器 LAN IP。

```nix
yunshu.container = {
  enable = true;
  mode = "gateway";
  networkMode = "bridge";
  bridge = "br0";
  lanAddress = "192.168.10.3/24";
};
```

### bridge 网络模式

容器 eth0 直接接入宿主机已有 bridge，拥有独立局域网 IP。

```nix
yunshu.container = {
  enable = true;
  networkMode = "bridge";
  bridge = "br0";
  lanAddress = "192.168.10.3/24";
};
```

宿主机需先创建 `br0`。宿主机 IP/NAT 故障时，只要物理网卡和 bridge 还正常，
容器仍可能继续工作。

### private_proxy + nat 模式

如果不方便建 bridge，可以使用私有 veth 和宿主机端口转发：

```nix
yunshu.container = {
  enable = true;
  mode = "private_proxy";
  networkMode = "nat";
  hostAddress = "10.100.0.1";
  localAddress = "10.100.0.2";
  forwardProxy = true;
  proxyPort = 7890;
};
```

此时局域网设备使用宿主机 IP 的 `7890` 端口。

## 7. 状态持久化

容器默认：

```nix
yunshu.container.persistState = true;
```

这等价于容器不是 ephemeral，容器 root 文件系统会保留。登录 token、`config.db`
和缓存位于容器内的 `/var/lib/yunshu`。

如果需要备份，可以在宿主机上找到容器 root 后复制：

```sh
sudo ls -la /var/lib/nixos-containers/yunshu-router/var/lib/yunshu
```

备份示例：

```sh
sudo tar -C /var/lib/nixos-containers/yunshu-router/var/lib \
  -czf yunshu-state.tar.gz yunshu
```

恢复时把该目录放回容器 root 对应位置，再重启容器。

## 8. 强制重新登录

当 token 过期或需要切换账号时：

```sh
sudo nixos-container run yunshu-router -- \
  rm -f /var/lib/yunshu/config/.logged-in
sudo nixos-container run yunshu-router -- \
  systemctl restart yunshu-login
```

然后重新查看登录日志：

```sh
sudo journalctl -M yunshu-router -u yunshu-login -f
```

## 9. 更新配置

修改宿主机 flake 后：

```sh
sudo nixos-rebuild switch --flake .#host
```

修改只影响容器 guest 时，也可以只重启容器：

```sh
sudo nixos-container restart yunshu-router
```

## 10. 常用命令

```sh
# 查看容器状态
sudo nixos-container status yunshu-router

# 进入容器
sudo nixos-container run yunshu-router -- bash

# 查看 yunshu 服务
sudo nixos-container run yunshu-router -- systemctl status yunshu-daemon
sudo nixos-container run yunshu-router -- systemctl status yunshu-updater

# 查看代理服务
sudo nixos-container run yunshu-router -- systemctl status 3proxy

# 查看登录日志
sudo journalctl -M yunshu-router -u yunshu-login -f
```

## 11. 选项速查

`yunshu.container` 主要选项：

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| `enable` | `true` | 是否启用容器 |
| `mode` | `"gateway"` | 运行模式：`gateway`、`private_proxy`、`public_proxy`、`tproxy` |
| `name` | `"yunshu-router"` | 容器名称 |
| `networkMode` | `"bridge"` | `bridge` 或 `nat` |
| `bridge` | `null` | bridge 模式使用的宿主机 bridge |
| `lanAddress` | `null` | bridge 模式下的容器 IP/前缀 |
| `hostAddress` | `"10.100.0.1"` | nat 模式宿主机侧 IP |
| `localAddress` | `"10.100.0.2"` | nat 模式容器侧 IP |
| `forwardProxy` | `false` | nat 模式是否转发代理端口 |
| `proxyPort` | `7890` | 代理端口 |
| `persistState` | `true` | 是否持久化容器 root 和登录状态 |
| `gateway.floatIp` | `"192.168.10.254"` | VRRP 浮动 IP |
| `gateway.vrrpId` | `10` | VRRP virtual_router_id |
| `publicProxy.auth` | `[ "iponly" ]` | 公网代理认证方式 |
| `publicProxy.allowFrom` | `[ ]` | 公网代理允许来源网段，public_proxy 模式必须配置 |
| `publicProxy.denyPrivate` | `true` | 公网代理是否拒绝私网目标 |
| `publicProxy.usersFile` | `null` | `auth` 包含 `strong` 时的 3proxy users file |

`services.yunshu` 主要选项：

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| `enable` | `true` | 是否启用 yunshu headless |
| `corpCode` | 登录企业码（按需填写） | 企业码 |
| `spAddr` | `"https://sp.eagleyun.cn/"` | SP 地址 |
| `loginOnStart` | `true` | 是否开机尝试登录 |
| `loginHttpListen` | `"0.0.0.0"` | 登录状态 HTTP 服务监听地址 |
| `loginHttpPort` | `8080` | 登录状态 HTTP 服务端口 |
| `package` | `../dist/yunshu-headless` | headless payload 路径 |

`services.yunshu.proxy` 主要选项：

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| `enable` | `false` | 是否启用代理，由 `mode` 控制 |
| `listen` | `"0.0.0.0"` | 监听地址 |
| `listenPort` | `7890` | 监听端口 |
| `denyPrivate` | `false` | 是否拒绝私网目标 |
| `auth` | `[ "none" ]` | 认证方式：`none`、`iponly`、`strong` |
| `usersFile` | `null` | `strong` 认证使用的 users file |
| `acl` | `[ ]` | 3proxy ACL 条目 |
| `threeProxyServices` | `[ ]` | 追加的 3proxy service |

`services.yunshu.dns` 主要选项：

| 选项 | 默认值 | 说明 |
| --- | --- | --- |
| `enable` | `false` | 是否启用 DNS 配置，`gateway` 默认开启 |
| `listen` | `"127.0.0.1"` | YunShu DNS 本地监听地址，DNAT 目标 |
| `port` | `53` | DNS 端口 |
| `transparentRedirect` | `false` | 是否透明重定向 53 端口流量 |

## 12. 排障

容器没有启动：

```sh
systemctl status container@yunshu-router
journalctl -u container@yunshu-router -n 100
```

代理端口不通：

```sh
sudo nixos-container run yunshu-router -- ss -tlnp
sudo nixos-container run yunshu-router -- systemctl status 3proxy
```

yunshu 没有网络：

```sh
sudo nixos-container run yunshu-router -- ip addr
sudo nixos-container run yunshu-router -- ip route
sudo nixos-container run yunshu-router -- journalctl -u yunshu-daemon -n 100
```

登录失败：

```sh
sudo journalctl -M yunshu-router -u yunshu-login -n 200
sudo nixos-container run yunshu-router -- \
  journalctl -u yunshu-daemon -n 200
```

## 13. 安全说明

- 该方案面向可信内网，默认 `3proxy` 不加密、不认证。
- 如果代理端口会暴露到不可信网络，应至少增加 ACL 或切换到带认证的代理配置。
- `yunshu` 需要 root、`CAP_NET_ADMIN` 和 `/dev/net/tun`，这是其运行模型决定的。
- 容器不是虚拟机隔离；如果需要强隔离，应评估其他隔离方式。
